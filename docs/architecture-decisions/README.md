# Architecture Decision Records (ADRs)

## Purpose

Architecture Decision Records (ADRs) capture significant architectural decisions made during the evolution of the TuskerBlueprint Platform.

Each ADR records:

* Context
* Decision
* Rationale
* Consequences
* Status

ADRs provide historical context for future contributors and prevent important architectural decisions from being lost in pull requests or discussions.

---

# ADR Lifecycle

1. Proposed
2. Accepted
3. Superseded
4. Deprecated

Accepted ADRs are considered part of the TPRA until superseded by another accepted ADR.

---

# Naming Convention

```text
ADR-0001-title.md
ADR-0002-title.md
ADR-0003-title.md
```

Numbering is sequential and permanent.

ADR numbers are never reused.
